Methods

Almost every theorem in the library is a combination of a few techniques. Each section explains one of them and gives an instance taken from the Lean source on the main branch. Terms are defined on the Background page.

The ℓ-adic ledger

How it works. For a fixed prime ℓ, take vℓ of σ(N) = 2N. The left side is the sum of vℓ(σ(pep)) over the components, the right side is vℓ(N) (plus 1 if ℓ = 2). If the exponent of ℓ in N is known, that is a fixed budget; any set of components that together put more than that many factors ℓ into σ(N) is a contradiction. In network language, this is conservation at the vertex ℓ.

Instance. If 3 has exponent exactly 2 and 7, 13, 19 have exponent exactly 2, then σ(7²) = 57 = 3·19, σ(13²) = 183 = 3·61 and σ(19²) = 381 = 3·127 put three factors 3 into σ(N) against a budget of 2.

theorem exclude_four_exact_squares {n : ℕ} (hn : n.Perfect)
  (h3 : n.factorization 3 = 2) (h7 : n.factorization 7 = 2)
  (h13 : n.factorization 13 = 2) (h19 : n.factorization 19 = 2) : False

OPNStarter.exclude_four_exact_squares in OddPerfect.Seed.Starter

The same scheme with ℓ = 3 proves Steuerwald's theorem when 3 divides N, with ℓ = 5 the exponent four case, and with ℓ = 7 the exponent six case: each ordinary prime p ≡ 1 (mod ℓ) whose exponent e satisfies ℓ | e + 1 contributes at least one factor ℓ, by lifting the exponent. With ℓ = 2 the ledger gives Euler's form.

Forcing chains

How it works. If p has exact exponent e in N, then σ(pe) divides σ(N) = 2N, so every odd prime dividing σ(pe) divides N. More generally, if a + 1 divides e + 1 then σ(pa) divides σ(pe), because a geometric sum of length a + 1 divides one whose length is a multiple of a + 1. Each forced prime has its own exponent, which may force further primes: a chain. The exponent must be known exactly, since σ(3²) = 13 while σ(3⁴) = 11².

Instance. σ(3²) = 13, and σ(13²) = 183 = 3·61. The second link needs its own hypothesis that 13 has exponent exactly 2.

theorem force_prime {n p e q : ℕ} (hn : n.Perfect) (hp : p.Prime)
  (he : n.factorization p = e) (hq : q.Prime) (hodd : q ≠ 2)
  (hdiv : q ∣ σ 1 (p ^ e)) : q ∣ n

OPNStarter.force_prime in OddPerfect.Seed.Starter

  61 ∣ n

Abundancy bounds and abundant divisors

How it works. Two uses of abundancy. Upward: a perfect number has no abundant divisor, so exhibiting a divisor d with σ(d) > 2d closes a case. Downward: the abundancy of N is below the product of p/(p − 1) over its prime factors, so a set of primes whose product is at most 2 cannot be the full support of N. The second use bounds the number and size of prime factors, the first closes the leaves of case analyses.

Instance. 3 and 7 are ≡ 3 (mod 4), so they cannot be the special prime and appear at least squared. If 105 = 3·5·7 divides N, then 3²·5·7² = 2205 divides N, and σ(2205) = 13·6·57 = 4446 > 4410.

theorem not_105_dvd (h : OddPerfect N) : ¬ 105 ∣ N

The closed loop exclusion

How it works. Suppose that for every ordinary prime r, σ(rer) is a power qcr of the special prime. Then all weight from ordinary primes goes to q, and the ordinary primes are fed only by q. The proof, in the steps of the source:

  1. conservation at r gives rer dividing σ(qk), which divides qk+1 − 1;
  2. qcr = 1 + r·σ(rer−1) is ≡ 1 modulo r but not modulo r², so lifting the exponent gives rer−1 dividing k + 1;
  3. k is odd, so 2∏ rer−1 divides k + 1;
  4. conservation at q gives k = Σ cr;
  5. a size comparison: with tr = rer−1, qcr = σ(rer) < rer+1 ≤ tr³ ≤ 5tr ≤ qtr, so cr < tr;
  6. so k + 1 ≤ 1 + Σ (tr − 1) ≤ ∏ tr, while step 3 gives ∏ tr ≤ (k + 1)/2: contradiction.
theorem not_all_components_special_powers {N q : ℕ} (h : OddPerfect N) (hq : q.Prime)
  (hodd : Odd (N.factorization q))
  (hpow : ∀ p ∈ N.primeFactors, p ≠ q → ∃ c : ℕ, σ 1 (p ^ N.factorization p) = q ^ c) :
  False

OddPerfect.not_all_components_special_powers in OddPerfect.ClosedLoop

This is the engine behind Steuerwald's theorem when 3 does not divide N (every σ(p²) is then a power of q), its prime length generalization, and the bound 3qk < 2m².

Primitive divisors and exponent caps

How it works. For a base a ≥ 3 and n ≥ 3 the library constructs a primitive prime divisor through the cyclotomic value Φn(a). If p has exponent e in N and d ≥ 3 divides e + 1, the primitive prime of order d divides σ(pe), hence N, and is ≡ 1 (mod d). Different d give different primes. This caps exponents by the largest prime factor and bounds the number of divisors of e + 1 by ω(N).

Instance. If 3 has exponent 4, take d = 5: σ(3⁴) = 121 = 11², and 3 has order 5 modulo 11, so 11 divides N, and 11 = 2·4 + 3 meets the cap 2e + 3 ≤ R exactly.

theorem exists_primeFactor_modEq_one {N p d : ℕ} (h : OddPerfect N)
  (hp : p ∈ N.primeFactors) (hd3 : 3 ≤ d) (hd : d ∣ N.factorization p + 1) :
  ∃ q ∈ N.primeFactors, orderOf (p : ZMod q) = d ∧ q % d = 1

OddPerfect.exists_primeFactor_modEq_one in OddPerfect.Zsigmondy

  (hp : p ∈ N.primeFactors) (hR : ∀ r ∈ N.primeFactors, r ≤ R) :
  2 * N.factorization p + 3 ≤ R

Finite kernel computations over explicit supports

How it works. When the theory reduces a statement to finitely many cases, the cases are encoded as a Boolean function whose value the Lean kernel computes with decide +kernel (see Procedure). A soundness lemma, proved once, says what a true value means.

Instance. For ω(N) = 4, abundancy bounds leave 104 explicit supports: {3, 5, r, s} with 17 ≤ r ≤ 31 and s < 256 (70 supports), {3, 7, r, s} with r ∈ {11, 13} and s ≤ 26 (6), {3, 5, 11, s} with s ≤ 100 (20) and {3, 5, 13, s} with s ≤ 46 (8). For a support S and a prime x in it, the candidate exponents e come from Euler's form and primitive divisors: e = 1 if x ≡ 1 (mod 4), or e + 1 = d ≥ 3 with d dividing y − 1 for some y in S. The function checkX tests that σ(xe) does not divide (2∏S)(e+1)x, which, because σ(xe) < xe+1 < 2(e+1)x bounds every exponent in σ(xe), means that σ(xe) has a prime factor outside S and 2. If some x of S admits no exponent, S carries no odd perfect number. The tables are four statements of the form below, each closed by decide +kernel.

private theorem tab13 : ∀ s < 47, 13 < s → isPrimeB s = true →
    checkSupport [3, 5, 13, s] = true := by
  decide +kernel

From OddPerfect/OmegaFive.lean

The McDaniel module uses the same idea as a finite forcing tree: from 3 and 13 it branches on whether each forced prime (13, 61, 97, 3169, 3348577, 3737657091169) is special, and each of the leaves has an abundant divisor, for example 3²·5²·13²·31 with abundancy about 2.00205.

Verified certificate checking

How it works. An untrusted program searches for a proof and writes it down as a certificate, a tree of rules. The library contains a checker check : List Fact → Cert → Bool and one soundness theorem: if the checker accepts a certificate for a state, no odd perfect number satisfies all facts of the state. The kernel only has to evaluate check; it never has to trust the search program.

Scope. An accepted certificate excludes every odd perfect number that matches its root facts, and nothing more. No family of root facts used in the library is proved to cover every odd perfect number, so the certificates give restricted exclusions, not a general one.

A state is a list of facts about the unknown N, each one of exact p e (the exponent of p is exactly e), powDvd p e (pe divides N) or notDvd p (p does not divide N). Primality inside the checker is a trial division test isPrimeB, proved sound. The rules and why each is sound:

force p e a q next (step)
Requires exact p e in the state, p and q prime, q ≠ 2, a + 1 dividing e + 1, and q dividing 1 + p + ⋯ + pa. Then σ(pa) divides σ(pe), which divides 2N, so the odd prime q divides N; checking continues with powDvd q 1 added.
split p e atExact atMore (step)
Requires p prime and pe dividing N recorded (directly or through an exact exponent). The two cases "the exponent is exactly e" and "pe+1 divides N" are exhaustive, and both subcertificates must be accepted.
abundant ps (closing)
A list of distinct primes p with recorded pe dividing N, and 2∏pe < ∏σ(pe). The product d of the pe divides N, its divisor sum is the product of the component sums, and d is abundant, so N would be abundant.
notDvd p e (closing)
pe with e ≥ 1 divides N while the state says p does not divide N.
exactPow p e e' (closing)
The state says the exponent of p is exactly e, and pe' divides N with e < e'.
parityTwo p e q f (closing)
Two distinct primes with odd exact exponents e and f contradict Euler's form, which allows only one.
paritySpecial p e (closing)
An odd exact exponent e at p with p ≢ 1 or e ≢ 1 (mod 4) contradicts Euler's form, since such a p would be the special prime.
overflow q e ps (closing)
The state says the exponent of the odd prime q is exactly e, and the listed distinct primes p, each with recorded exact exponent f ≥ 1, have qk dividing σ(pf) with the claimed k adding up to more than e. This contradicts the q-adic ledger.

Instance. Exponent exactly 2 at both 3 and 5: force 13 from σ(3²) and 31 from σ(5²), then split on the exponent of 13. If it is 1, σ(13) = 14 forces 7, and 3²·5²·13·7 is abundant; otherwise 3²·5²·13²·31 is abundant.

theorem exclude_three_sq_five_sq {N : ℕ} (h : OddPerfect N)
  (h3 : N.factorization 3 = 2) (h5 : N.factorization 5 = 2) : False

OddPerfect.Cert.exclude_three_sq_five_sq in OddPerfect.Certificate

check_sound (s := [.exact 3 2, .exact 5 2])
  (c := .force 3 2 2 13 <| .force 5 2 2 31 <|
    .split 13 1
      (.force 13 1 1 7 <| .abundant [(3, 2), (5, 2), (13, 1), (7, 1)])
      (.abundant [(3, 2), (5, 2), (13, 2), (31, 1)]))
  (by decide +kernel) N h (by simp [State.Holds, Fact.Holds, h3, h5])

Pratt primality certificates

How it works. A prime p is certified by a number a whose order modulo p is exactly p − 1: ap−1 ≡ 1 (mod p), and a(p−1)/f ≢ 1 (mod p) for each prime factor f of p − 1. That requires the factorization of p − 1 and the primality of its factors, so the certificate is a flat list of entries (p, a, fs) in dependency order, where fs lists the prime factors of p − 1 with multiplicity. The checker verifies, for each entry, that the product of fs is p − 1, that every element of fs is an earlier entry or passes trial division, and the power conditions, using binary modular exponentiation written with structural recursion so that the kernel can evaluate it. mathlib's lucas_primality turns an accepted entry into a proof of primality.

Instance. 1093 = σ(3⁶) appears in the exponent six chains. Its certificate is the single entry (1093, 5, [2, 2, 3, 7, 13]): 2·2·3·7·13 = 1092, 51092 ≡ 1 (mod 1093), and 51092/f ≢ 1 for f = 2, 3, 7, 13.

theorem prime_1093 : Nat.Prime 1093

OddPerfect.Pratt.prime_1093 in OddPerfect.Pratt

theorem prime_1093 : Nat.Prime 1093 :=
  prime_of_checkPrime (c := [(1093, 5, [2, 2, 3, 7, 13])]) (by decide +kernel)

Quadratic residue constraints

How it works. σ(pa) ≡ 1 (mod p), so its Legendre symbol modulo p is 1, and expanding over its factorization gives a sign identity at every vertex of the network. In the other direction, if e is even and r divides σ(pe), then pe+1 ≡ 1 (mod r) with e + 1 odd, so p is a square modulo r.

Instance. The special prime q receives weight from some ordinary p, so p is a square modulo q; since q ≡ 1 (mod 4), reciprocity makes q a square modulo p. This is exists_mutual_quadratic_residues, tagged novelty unverified.
