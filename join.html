Contribute a proof

The library grows one checked theorem at a time, and you can add one. Each open step below is an exact Lean statement that the library does not prove yet. A contribution is one Lean file that proves one step. The Lean kernel decides whether it is accepted; who wrote it, a person or an AI agent, makes no difference.

What this is not. No step settles the conjecture. Whether an odd perfect number exists is open, and this project has not solved it. Most steps restate a published theorem that the library lacks.

How it works

  1. Pick a step.Choose one from the table that has no proof yet and no open pull request titled Step <Name>.
  2. Say you took it.Fork the repository and open a draft pull request with that title. A draft with no new commit for 14 days counts as released.
  3. Write one file.Add Contributions/<Name>.lean with one theorem OddPerfect.Proofs.<Name> whose statement is exactly OddPerfect.Steps.<Name>. Change nothing else.
  4. Check it.Run the format scan and the contribution gate on your machine; both ship with the repository.
  5. Submit.Mark the pull request ready. The repository's checks run, a maintainer reads the file, and an accepted proof is added to the main branch by the maintainers and credited to you here.

The full rules, the file format and the commands are in CONTRIBUTING.md. AI agents can read the same rules as plain text: join.txt.

Open steps

The statements live in OddPerfect/Steps.lean; that file is the authority, and the table is a summary. All nine steps posted so far are closed; new steps will be added here.

The two classical steps are the hypotheses of the conditional theorems in ConditionalSupport. The library has since proved the conclusions of those theorems without them (EscapeRowUnique), and both steps are closed (NagellPrime, ThreeRowPrime).

The published steps were restated by us from the cited page and tested on small cases. A restatement can still be wrong. If you find a counterexample to a step, open an issue; it is credited like a proof.

How a contribution is checked

  • Format scan. Before anything compiles the file, a scan rejects whatever could run a program during elaboration or switch off the kernel: commands that start with #, new syntax, attributes other than @[simp], options other than two resource limits, string literals.
  • Gate. The file is compiled outside the library. A gate then reads the compiled result: the theorem must exist, its statement must be the posted step and nothing else, and every declaration in the file may depend only on the three standard axioms.
  • Review. A passing check is necessary and not sufficient. A maintainer reads the whole file and repeats the checks on a separate machine.

Credit

The person who submitted an accepted proof is credited here by step, and in the header comment of the file. Credit goes to a person or to a named account, not to a tool.
