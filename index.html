Does an odd perfect number exist?

A Lean 4 project that formalizes what is known about odd perfect numbers, with every theorem checked by the Lean kernel, and that searches for a way to settle the question.

The conjecture is open. This project does not claim a proof. Everything listed here is a necessary condition that any odd perfect number would have to satisfy. Almost all of it is known mathematics, now machine checked. A small number of statements are marked as novelty unverified.

σ(N) = 2N, with N odd

A number is perfect when the sum of its divisors equals twice the number. The even perfect numbers were described by Euclid and Euler. Whether an odd one exists has been open for centuries.

Status

The target is stated once, as a proposition, and is never assumed anywhere in the library.

def OddPerfect (N : ℕ) : Prop := Odd N ∧ N.Perfect

def OddPerfectConjecture : Prop := ∀ N : ℕ, ¬ OddPerfect N

What is proved

Structural theorems about a hypothetical odd perfect number N: its shape, congruences, bounds on its prime factors and exponents, exclusion of whole families of exponent patterns, and finiteness statements.

What is not proved

The conjecture itself. The project will report a resolution only if a theorem of type OddPerfectConjecture, or its negation, compiles with the three standard axioms of Lean and mathlib.

An exact reformulation

The library proves that the conjecture is equivalent to the nonexistence of a finite, balanced network of prime powers (conjecture_iff_no_balanced). All later work is phrased against that network.

Procedure

The work is organized as a pipeline in which drafting is cheap and trust comes only from the Lean kernel. Proof drafts are written by AI coding agents working in parallel. A supervising session verifies each result before it enters the repository.

  1. Fix the statement.The definitions of an odd perfect number and of the conjecture are written first and kept minimal, so that every later theorem can be read against them.
  2. Survey the literature and existing code.Papers and public repositories are screened, the relevant ones are read in full, and each gets a note: the method, the lemmas worth formalizing, and any step that does not hold up.
  3. Assign one module per agent.Each agent receives a precise target statement, the proof standards, and pointers to the existing library. Agents write proofs from scratch, test claims numerically with exact arithmetic before formalizing them, and may only check their own file.
  4. Report deviations.An agent must say exactly what it proved, what it could not prove, and where it changed a statement. Statements found to be false are corrected and the counterexample is recorded.
  5. Verify independently.For every returned module the supervising session scans for forbidden constructs, runs a full build of the whole library, parses every axiom report printed by the build, and reads the headline statements against their intended meaning.
  6. Commit only verified work.A module is committed and pushed only after the full build succeeds and every axiom report is clean.
  7. Test ideas against countermodels.Objects that satisfy most of the constraints without being odd perfect numbers, such as spoof factorizations, are kept as formal test cases. A proposed global argument that these objects also satisfy cannot be a proof.
  8. Steer the next wave.A review of the library, the notes, and the countermodels produces a ranked list of next targets, and the cycle repeats.

Trust policy

A reader should need to trust only the Lean kernel, mathlib, and the statements themselves.

No escape hatches

The library contains no sorry, no admit, no added axiom, no native_decide, and no unsafe or implemented_by declarations.

Three axioms only

Every file ends with #print axioms lines. Each public theorem depends on at most propext, Classical.choice, and Quot.sound.

Computation inside the kernel

Finite case analyses are run by verified checkers and evaluated with kernel reduction (decide +kernel). Primality of large numbers uses Pratt certificates checked the same way.

Pinned environment

Lean 4.33.1 with a pinned mathlib revision. The whole library is rebuilt before every commit.

Untrusted inputs

Papers and third party code are read as data only. Nothing from them is executed or copied into the library, and every borrowed statement is proved again from scratch.

Honest naming

Partial results carry their exact hypotheses in the statement. A theorem is never weakened silently to make a proof go through.

Selected theorems

Throughout, N is an odd perfect number, q is its special prime (the one prime with an odd exponent), and the other primes are called ordinary. ω counts distinct prime factors and Ω counts prime factors with multiplicity. Names are the Lean identifiers.

known, formalized

Euler's form

N = qkm² with q prime, q not dividing m, and q ≡ k ≡ 1 (mod 4).

theorem exists_euler_form (h : OddPerfect N) :
  ∃ q k m, q.Prime ∧ N = q ^ k * m ^ 2 ∧
    ¬ q ∣ m ∧ q % 4 = 1 ∧ k % 4 = 1
known, formalized

Touchard's congruence, refined

N ≡ 1 (mod 12), or N ≡ 117 (mod 468), or N ≡ 81 (mod 324).

theorem mod_refined (h : OddPerfect N) :
  N % 12 = 1 ∨ N % 468 = 117 ∨ N % 324 = 81
known, formalized

At least five prime factors

ω(N) ≥ 5. Without the prime 3 at least seven, and without 3 and 5 at least fifteen.

theorem five_le_card_primeFactors
  (h : OddPerfect N) : 5 ≤ N.primeFactors.card
known, formalized

Upper bound

N is smaller than 2 to the power 4ω(N). Hence finitely many candidates for each ω.

theorem lt_two_pow_four_pow (h : OddPerfect N) :
  N < 2 ^ (4 ^ N.primeFactors.card)
known, formalized

Equal exponent patterns

The ordinary exponents cannot all be 2, all be 4, all be 6, or all be congruent to 2 modulo 3.

theorem steuerwald (h : OddPerfect N) (hq : q.Prime)
  (hodd : Odd (N.factorization q))
  (hsq : ∀ p ∈ N.primeFactors, p ≠ q →
    N.factorization p = 2) : False

Also mcdaniel, not_all_exponents_four, not_all_exponents_six.

known, formalized

Small primes cannot all be present

105 does not divide N. The smallest prime factor p satisfies 3p < 2ω + 6.

theorem not_105_dvd (h : OddPerfect N) : ¬ 105 ∣ N
theorem three_mul_minFac_lt (h : OddPerfect N) :
  3 * N.minFac < 2 * N.primeFactors.card + 6
known, formalized

Counting inequalities

Total and distinct prime factor counts are linked, after Zelinsky (arXiv 1706.07009).

theorem eight_mul_omega_le_of_not_three_dvd
  (h : OddPerfect N) (h3 : ¬ 3 ∣ N) :
  8 * ω N ≤ 3 * Ω N + 7
theorem twentyone_mul_omega_le (h : OddPerfect N) :
  21 * ω N ≤ 8 * Ω N + 39
known, formalized

The special prime power is small

In Euler's form, 3qk < 2m².

theorem special_pow_lt_sq ... :
  3 * q ^ k < 2 * m ^ 2
novelty unverified

One exception forces 3

If every prime other than q and one further prime r has exponent exactly 2, then 3 divides N. The proof uses only abundancy bounds. The setting is that of Ochem and Zelinsky (arXiv 2607.19746). Whether this route is new has not been checked.

theorem three_dvd_of_one_exception
  (h : OddPerfect N) (hq : q.Prime)
  (hodd : Odd (N.factorization q))
  (hr : r.Prime) (hrq : r ≠ q)
  (hsq : ∀ p ∈ N.primeFactors, p ≠ q → p ≠ r →
    N.factorization p = 2) : 3 ∣ N
novelty unverified

Mutual quadratic residues

N always has two prime factors that are quadratic residues of each other. This removes a congruence hypothesis from a theorem of Wallace (arXiv 1610.00544). Whether the stronger form is new has not been checked.

theorem exists_mutual_quadratic_residues
  (h : OddPerfect N) :
  ∃ p ∈ N.primeFactors, ∃ r ∈ N.primeFactors,
    p ≠ r ∧ jacobiSym p r = 1 ∧ jacobiSym r p = 1
known, formalized

Exponents are capped by the largest prime

If every prime factor is at most R, then every exponent e satisfies 2e + 3 ≤ R.

theorem two_mul_factorization_add_three_le
  (h : OddPerfect N) (hp : p ∈ N.primeFactors)
  (hR : ∀ r ∈ N.primeFactors, r ≤ R) :
  2 * N.factorization p + 3 ≤ R
tool

Certificate checker

A small verified checker for factor chain arguments. A certificate that passes the check excludes every odd perfect number matching the given exponent pattern.

theorem check_sound (hc : check s c = true) :
  ∀ N, OddPerfect N → State.Holds s N → False

Why the problem resists

Some objects satisfy almost every known constraint without being odd perfect numbers. They show which kinds of argument cannot succeed. The Descartes spoof is in the library as a formal test, and the signed spoof module is in verification.

The working conclusion: a proof of nonexistence must combine primality of every node of the network, positivity and size, the 2-adic budget, finiteness of the support, and exact equality in one global step. No known result does this. The theorems above that combine exact structure with inequalities, such as the one exception theorem, are small instances of that shape.

Literature and code survey

The survey feeds the list of targets and guards against repeating known mistakes.

Papers

287 arXiv papers on perfect numbers and related topics were screened by title and abstract. 131 were graded as directly relevant or transferable and read in full from their sources, each with a written note.

Repositories

101 public repositories matching the topic were reviewed by reading only. A handful contain useful certificates or lemma statements, which were reproved here rather than copied.

Claimed proofs

Sixteen papers that claim to settle the conjecture or a related open statement were read as a referee would. In each case our reading found a step that does not follow. These readings have not been externally reviewed.

What the survey produced

Target statements for the modules above, a list of results still missing from the library, and the countermodel checklist used to test new ideas.
