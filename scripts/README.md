# Search and generator scripts

These are programs that found certificates, proof trees, tables and primality witnesses used in the Lean library `OddPerfect`. The folder is not complete; see the last section. Nothing in this folder is trusted: every certificate these scripts produce is checked again by the Lean kernel inside the library, so a bug here can make a search fail but cannot make a false theorem pass. The scripts exist so that the searches can be repeated and extended.

## Requirements

* Python 3 (version 3.12.14 was used; the reruns of 2026-11-22 also used 3.12.3, see the run records). Most scripts need only the standard library.
* sympy (version 1.14.0 was used) for `ExponentTenTwelve/gen.py`, `ExponentTenTwelve/explore.py`, `CommonPrimeChain/gen.py`, the three scripts in `CommonFamily/`, `CommonFamilies/search.py`, `verify.py` and `gen2.py`, `KanoldFive/check.py`, `EqualExponentChainMore/gen2.py` and `nt.py`, `Restrained/gen13.py`, `TwoExceptionTwo/search.py` (factoring with `factorint`, primality with `isprime`, also `nextprime`, `n_order`, `divisors`, `mobius`, `primerange`; its output depends on the sympy version, see its row) and `TwoExceptionTwo/gen.py` (Pratt certificates).
* sympy for `DefectTree/search.py`, only for rows missing from `DefectTree/rows.json` (none for the stored certificates); `DefectTree/gen.py` and `check.py` need the standard library only.
* sympy also for `ExcessFour/search.py` (factoring and primality as in `TwoExceptionTwo/search.py`; sympy 1.14.0 and 1.12 give the same three certificates) and `ExcessFour/gen_excess.py` (Pratt certificates, through `TwoExceptionTwo/gen.py`). `gen_excess.py` imports `engine.py` and `gen.py` from the folder `TwoExceptionTwo` next to its own folder, so the two folders must stay side by side.
* `LowerBound/gen.py` and `LowerBound/emit.py` use cypari2 (version 2.2.4 was used) for factoring; without it they fall back to Pollard rho and ECM. For the command of the library (`emit.py 79 trees.lean 3: 5:3 7:3,5`) the fallback writes the same file byte for byte, in about 28 CPU seconds instead of about one; for other parameters it may build a different tree.
* `LowerBound/gentwo.py` needs sympy and no cypari2: it loads `pftwo.py` in place of `pf.py`; `pftwo.py` factors with sympy (BPSW test, Pollard rho, Pollard p - 1) and `ecm.py` at a fixed effort, so its output does not depend on the speed of the machine. sympy 1.14.0 was used for the Lean data; search runs with sympy 1.12 on the same hints gave the same instructions.
* numpy for `ForcingClosedBound/check.py` (versions 2.5.3 and 1.26.4 were used).
* `ThreeFreeThree/` reads its compressed certificate with the standard module `lzma`, present in most Python builds; so do `TwoExceptionTwo/gen.py`, `check.py` and `engine.py` (`xz -dk cert.jsonl.xz` writes the decompressed `cert.jsonl`, which they also accept).
* `xz` for the certificates `CommonFamilies/certs/cert_d55.json.xz`, `cert_d85.json.xz` and `cert_d115.json.xz`: `xz -dk certs/cert_d55.json.xz` writes `certs/cert_d55.json`, likewise for `85` and `115`; `CommonFamilies/rebuild115.sh` decompresses its certificate itself.
* A C compiler for `EqualExponentChain/osearch.c`: `cc -O2 -o osearch osearch.c`. `EqualExponentChainMore/gen2.py` uses the same program, looked up in the folder `EqualExponentChain`. Also for `ForcingClosedBound/gen.c`: `cc -O2 -o gen gen.c -lm`.

Each script starts with a header that says what it computes, which Lean declaration uses the result, how to run it and roughly how long it takes. Scripts read and write their data files in the current folder and find their helper files next to themselves, so they can be run from any folder. Run the scripts of `ForcingClosedBound/` in isolated mode, `python3 -I`: that folder holds a script `enum.py`, which shadows the standard module `enum` when the folder of the script is on the module path. With Python 3.12.3, where `enum` is not loaded at startup, `python3 solve.py 1000 cand_1000.txt` stops at its `import json` with an `AttributeError` (a circular import of `re`); with `python3 -I` the folder of the script is not on the module path and the run succeeds. (With Python 3.12.14 on the local machine `enum` is already loaded at startup and the plain command runs too.) Isolated mode does not suit every script: `AttackSize/c.py` imports its helper `util.py` from its own folder and stops under `-I` with `ModuleNotFoundError`; it runs as `python3 c.py`. The command lines in this README say where `-I` is used.

## Validator controls

`Controls/validator_controls.py` checks that the validators fail closed, for people and automation that read only the exit status: `EqualExponentChain/checker.py`, `LowerBound/check.py`, `CommonFamilies/verify.py` and `CommonFamilies/est.py`, and also the helpers of `ThreeFreeThree/`, `SecondLargestPrimeFast/validate.py` (with `knuth.py`, `reach.py`, `mkfast.py`), `LedgerThreeFree/check.py`, `MixedIndex/verify.py`, `MixedIndexThree/verify3.py` and `cert3.py`, the process count argument of `LargestPrimeFactor/gen6.py`, the mirror `TwoExceptionTwo/engine.py` (among others both paths of its tail test, on leaves built by the controls because no archived certificate reaches the second path; both paths of `TwoExceptionTwo/check.py` are controlled the same way, on leaves passed to its deficient leaf check at x = 101 and x = 107: no archived certificate reaches its second path, and a certificate holding only such a leaf would skip unlisted primes below x), `Controls/source_scan.py` and the module list of `Controls/replay.sh` (about two minutes in all). The first three use the same exit status convention: 0 when everything given passes, 1 when a well formed input fails a check (a rejected certificate, table or tree, a deficient case, a missing or extra case, a claim that differs from `--expect`), 2 for malformed input or a usage error (unreadable JSON, duplicate keys, an unknown node tag or a wrong number of fields, duplicate rows or cases, a residue outside `0 ≤ r < m`, no certificate or tree given, a requested tree absent from the file). `est.py` stops with status 1, before it writes anything, when a target cannot be reached (a whole pass adds no node), where it used to loop forever. None of the four relies on `assert`, so `python3 -O` gives the same verdicts.

Without `--expect`, OK from `verify.py` means only that the certificate proves the statement it declares itself. To check a certificate against the claim of a named theorem, state that claim; for the certificates in `certs/`:

    python3 -I verify.py --expect '{"d": 5, "seeds": [5, 7], "special_test": [12, 1], "excluded_primes": [], "exponents": {}}' certs/cert_d5_7.json
    python3 -I verify.py --expect '{"d": 65, "seeds": [5, 13], "special_test": [12, 1], "excluded_primes": [], "exponents": {}}' certs/cert_d65.json

The control script runs each validator as a subprocess, in normal and in optimized mode, on every archived valid input (status 0 expected) and on mutated copies built in a temporary folder (unknown node tag, extra field on the node `mod4`, a well formed certificate that fails, truncated JSON, a changed split instruction and a wrong table witness in a copy of `OddPerfect/LowerBound.lean`, a deficient singleton certificate, a conflicting duplicate case, a missing case, an extra case, the empty residue profile `(1, 1)`, the excluded prime `1`, a duplicate row, a claim that differs from `--expect`, and an `est.py` table whose target cannot be reached, run with a 20 second limit). Each mutation must give its exact expected status and no Python traceback. It also checks that none of the four validators contains an `assert`. It writes nothing inside the repository, prints one line per control and a final count, and exits 0 only if every control behaves as expected. Run it from any folder (about half a minute):

    python3 -I scripts/Controls/validator_controls.py
    python3 -I scripts/Controls/validator_controls.py --stdlib-only

The same script holds the controls of the helpers under `ThreeFreeThree/` (standard library only, so they run in both forms). `check3.py` used to accept three malformed leaves: a fifth weight (the four slot loop ignored it, the tail sum did not), a negative square witness `s` (the test `d = (2 s + 1)^2` cannot tell `s` from `-(s + 1)`), and a leaf with three slots. It now requires exactly four slots and four weights and natural number witnesses; each of the three forged certificates was accepted before the change and is rejected now with status 1. `verify3.py` rejected all three before and after. Three runs that printed their failures now also end with status 1: `gen_lean.py <certificate> mirror` on a disagreement, `route3.py` on a routing failure, and `verify3.py --tamper` when a tamper is not rejected (controlled with a copy of `verify3.py` whose tamper loop skips the verifier). The controls also run both checkers, the tamper list, the mirror and the deterministic part of `route3.py` (`<certificate> 0 1`) on the published certificate, and regenerate the twelve modules with `gen_lean.py <certificate> data` into the temporary folder and compare them byte for byte with the files in `OddPerfect/`. None of this changes a Lean file or the certificate.

Further controls, each in normal and in optimized mode where the script is Python: `MixedIndex/verify.py` and `MixedIndexThree/verify3.py` accept the archived certificates and reject an empty abundance set at the root (accepted before under `python3 -O`), a forced prime that is negative, a float or composite (all three accepted before under `python3 -O`) and, for `verify3.py`, a configuration with the base component `3^6` twice (accepted before also in normal mode); `cert3.py` with node limit 0 ends with status 1 and writes no tree; `knuth.py`, `reach.py` and `mkfast.py` reject zero probes, a zero chunk size, `LO = 10002` and wrong argument counts with status 2. `gen6.py` reads its process count only after the whole search, so its control does not run it: it evaluates the assignment of `jobs_at` in the source for both modes against the place of `[J]` in the two usage lines of the header, and checks that a copy with the former index 7 fails that comparison. The source scan controls write small files to the temporary folder: an attribute named `«command_elab»`, a tactic block inside `s!"…"`, a lakefile key `"more\u004cean\u0041rgs"` and an unreadable lakefile must be findings (status 1); the same words in comments, docstrings, ordinary strings and a lakefile value must not. The controls of `replay.sh` put a stand in for `lake` first on `PATH` (it prints a prefix with an empty `leanchecker` and logs each module it is asked to replay): the default list must be every file `OddPerfect/**.lean`, and on a small tree in the temporary folder an import written with two spaces must still be listed, while an empty selection and a file that the root file does not import must end with status 2. These controls need `sh` and a `python3` on `PATH` with `tomllib`. `TwoExceptionTwo/engine.py` accepts the four published certificates and `TwoExceptionTwo/check.py` the two exception certificate; the mirror rejects negative Rankin numerators, a pseudoprime beyond the deterministic range of its primality test, a scan past 1000 positions, a scan that reaches a prime beyond the trial division fuel of `findDiv` (4295098403, above 65537^2; as in Lean, `smallPrime` is false there), a square root where Newton does not settle within the 400 steps of `sqrtIfSq` (the square (2^500 + 1)^2 and a nonsquare that passes the square filter of `qrTable`, which the mirror now uses as its own filter) and the archived certificate with a second composite witness 1 for the candidate 581 of record 7817 (Lean reads the first pair, `comps.lookup`); the last three cases were accepted by the mirror before and are rejected by the definitions in `OddPerfect/TwoExcEngineCode.lean` (read, not evaluated in Lean). The mirror also checks every term by constructor against the Lean types `Cert` and `DefData` before any evaluation, so it rejects the archived certificate with the item [3169, 1] of record 12, which evaluation never reaches, replaced by ["leaf", 1] or [[], 1] (both accepted before); and its square root, Newton step and trial division give the Lean values at zero inputs (`sqrtIfSq 0` has the root 0, `newton 1 7 0 = 0`, `findDiv 2 7 0 = 1`, read from the definitions; the mirror raised `ZeroDivisionError` before). `check.py` rejects a forged root closure. `Controls/contribution_scan.py` accepts the format example and rejects ten forged files and a pull request that changes a second file.

The controls of `verify.py` need sympy; without it the first form fails, and the second skips them and lists each as SKIP; the same holds for the controls of `LedgerThreeFree/check.py`, `MixedIndex/verify.py`, `MixedIndexThree/verify3.py` and `cert3.py` (which imports sympy through `MixedIndex/search.py`). The validators run as subprocesses of the interpreter that runs the control script, so a virtual environment interpreter gives them its own packages, also in isolated mode (`-I` drops `PYTHONPATH` and the user site folder, not the site folder of the environment).

The continuous integration workflow runs the first form, all controls, before the build. The system Python of the runner has no sympy and is externally managed, so the workflow creates a virtual environment outside the checkout and installs into it exactly the pinned wheels of `Controls/requirements-sympy.txt` (sympy 1.14.0 and mpmath 1.3.0, both pure Python `py3-none-any` wheels, so the hashes hold on every platform) with `pip install --require-hashes`; pip refuses a file with any other hash. The requirements file says how to regenerate its hashes. The next step runs `CommonFamilies/rebuild95.sh` with the same interpreter, which the script takes from the environment variable `PYTHON` (default `python3`):

    python3 -m venv /tmp/venv
    /tmp/venv/bin/python -m pip install --require-hashes -r scripts/Controls/requirements-sympy.txt
    /tmp/venv/bin/python -I scripts/Controls/validator_controls.py
    PYTHON=/tmp/venv/bin/python bash scripts/CommonFamilies/rebuild95.sh . /tmp/rebuild95

Local run of these four steps (2026-11-22, Python 3.12.2 of python.org, a copy of `scripts/` and `OddPerfect/` in a scratch folder, a `PATH` whose `python3` has no sympy): pip installed `mpmath-1.3.0 sympy-1.14.0`; the controls printed `validator controls: 56 passed, 0 failed, 0 skipped`, exit 0 (73 with the controls of `ThreeFreeThree/` added later: 49 passed and 24 skipped with `--stdlib-only` on a machine without sympy); the rebuild printed `byte equal: 19 of 19 modules`, exit 0 (5.6 s wall).
